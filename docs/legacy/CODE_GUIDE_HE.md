# מפת הקוד

| רכיב | אחריות |
|---|---|
| app.py | יוצר את אפליקציית Flask, מחבר מסכי עבודה ושומר על חסימת מסלול הסריקה הישן |
| security.py | כניסת מפעיל, session, הגנת CSRF וכותרות הגנה לממשק |
| config.py | נתיב מסד הנתונים ורשימת הפעולות המוכרות |
| database.py | יצירת הטבלאות ועדכונים שמוסיפים מבנים בלי למחוק תוצאות |
| engagement_store.py | בדיקת טפסי סקופ ושמירת התקשרויות כטיוטה, ולאחר מכן אישור |
| scope_engine.py | התאמת היעד לכללי הכללה והחרגה, ללא DNS או HTTP |
| policy_engine.py | בדיקת הרשאה לסוג הפעולה וקבלת המכסה המותרת |
| rate_limit.py | שמירת מקום אטומית בחלון זמן מתגלגל, לפני ביצוע חיבור |
| execution.py | פעולות HTTP, DNS, TLS ו-TCP מוגבלות ומבוקרות |
| workbench_store.py | הרצות, תצפיות, הערות סקירה והיסטוריית החלטות |
| workbench.py | מסכי כלים, סקירה, ייבוא, תכנון בקשות והפקת דוח |
| engagements_ui.py | מסכי הגדרת התקשרות, preview ופעולת GET מקומית קיימת |
| importers.py | קריאת XML של Burp/Nmap בזיכרון ויצירת תצפיות ללא הרצה |
| pt_toolkit | ניתוח מידע שנלכד, מלאי נכסים, השוואה ותכנון בקשות ללא שליחה |
| local_http.py / audit_log.py / investigation_store.py | מסלול המעבדה המקורי, ששומר על התנהגותו ועל ההיסטוריה |
| templates/ ו-static/ | מבנה מסכים, צבעים, טפסים ועיצוב להדפסה |
| tests/ | בדיקות אוטומטיות עם DB זמני ותחליפי רשת |

בפעולה רגילה, הטופס שולח POST מוגן-CSRF. נוצר רישום pending. נבדקים scope ו-policy, ושמירת המכסה מתבצעת בתוך transaction. רק אחר כך נפתח חיבור מוגבל. התוצאה עוברת לניתוח, תצפיות מסוכמות נרשמות, והמפעיל מקבל מסך סקירה. תגובות רשת אינן הופכות לקוד ואינן מוצגות כ-HTML פעיל.

התצפיות מתחילות unreviewed. שינוי ל-confirmed דורש הערה; פירושו שהמפעיל בדק את התצפית. זה לא בהכרח אומר שהוכחה חולשה שניתנת לניצול. הדוח מציג במפורש את ההבחנה הזאת.

שמות הקבצים scanner_nmap.py ו-scanner_web.py נשארו לצורך התאמה לפרויקט הישן. אין מסלול חדש שמפעיל אותם. מסך יבוא Nmap קורא קובץ שכבר נוצר מחוץ ליישום.
